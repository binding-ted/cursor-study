00 · 开场

Cursor 是什么，为什么值得公司花时间学 What is Cursor · and why it matters for our team

一句话：Cursor = 能读懂整个项目、能直接动手改文件的 AI 工作台。新版默认打开的是 Agents Window（代理窗口）——你派活，它干活，改完给你审核。它不只是"聊天问答"。

先破除一个误解

很多同事以为"这是给程序员用的"。不是。 对我们绝大多数不写代码的人来说，Cursor 更像一个 能读懂你所有文件、并且真的会动手帮你改 的助理。

普通 AI 聊天

你复制文字进去 → 它回文字 → 你再复制回来贴。文件它看不见，也动不了。

Cursor · Agents Window

默认工作台。看你文件夹、改文件、跑命令、上传 GitHub。省去所有来回复制。

结果差别

一个是"给建议"，一个是"把事做完并给你审核"。

产出物地图：你交给它什么，它能交回什么

先建立心智：Cursor 不是又一个聊天框，而是在文件夹里把事做完的工作台。常见产出如下（本场会亲手练其中几项）：

类型你交给它它交回什么（举例）
文档提纲、纪要草稿、旧周报周报、会议纪要、SOP、变更记录、邮件稿

图与看板数据、流程说明流程图/示意图、Canvas 销售看板（柱状图、KPI）；复杂设计仍用专业工具
网页 / 小工具需求一句话本地 HTML 表单、查询页、培训页；部署到网上、手机可访问——后文再专讲

一句话
能交回的是「落在文件夹里的成品」——文档、表、页、脚本——再由你审核；不是只回一段建议文字。

01 · 界面 · 主讲

主界面：Agents Window（默认打开） Agents Window — your default workspace

新版 Cursor 打开后，多数情况默认进的是 Agents Window：左边是对话/任务列表，中间跟 AI 说话并选模式，右边（或下方）能看到它改了哪些文件——点文件就能打开看内容。下面这个模拟窗口可以点。

场地 · Agents Window（主讲）
Agents Window · 操作手册项目
① 任务 / Agent 列表
箱单 /X→/105✓ 已完成
改周报销售段● 进行中
做教学课件○ 草稿
② 对话 · 选模式再下命令
③ 改动的文件 · 点开看

点芯片 = 打开案例文件（摘录真实内容）

👆 试试：点左侧不同任务 → 切 Ask/Plan/Agent/Debug → 点右侧文件芯片打开内容。
Debug 示例在说什么：箱单要把「总箱数」改成 105，但表格里还有「位号」（零件编号，如 PPP-PCS-MAR-104）——里面的 104 不是箱数，改错了要会查、会回退。

① 左侧 · 任务列表
每个 Agent 对话像一张工单。可并行多个；点哪个就看哪个的进度。
② 中间 · 模式 + 对话
下拉与 IDE 侧栏一致：Agent / Plan / Debug / Multitask / Ask。Shift+Tab 也可切；Agent 快捷键常见为 Ctrl+I。
③ 右侧 · 成果文件
改了什么一目了然。点开看全文摘录——比只看一句「已完成」清楚得多。
⚠️ 打开项目的正确姿势
仍然要用 打开文件夹（不是单个文件）。Cursor 要先索引整个文件夹，才能跨文件帮你干活。
⚠️ 对话跟项目走
左侧 Workspaces 按项目分开历史对话——派活前先点对项目名。New Chat / New Agent 现版差不多，不必纠结名字。要开另一个项目文件夹：菜单 File → Open Folder（或顶栏点当前项目名 → On This PC → Open Folder）。

环境与工具链：开工前电脑要有什么

Cursor 经常要读表、跑脚本、看图。缺辅助程序时，Agent 会卡住——不是它不会，是本机没有工具。除 Office 外，下列优先选免费方案。

① 几乎人人要

  • Cursor — 本工作台
  • WPS 或 Microsoft Office — 看/改 xlsx、docx（箱单主线强依赖）
  • 浏览器 — 预览 HTML、看板
  • Git（Git for Windows）— 备份与协作（第 07 章）；装完用 git --version 验证

② 按场景选装（免费优先）

你要做的事建议安装备注
改 Word / Excel / 箱单WPS 或 OfficeOffice 通常需授权；WPS 个人版可先用
扫描件 → 可编辑文字OCR 工具按公司合规选用本地/网盘 OCR
批量改名、转格式、清洗数据Python装完终端执行 python --version
推送到 GitHub / 版本备份Git装完终端执行 git --version（见下方验证）
看 / 转 DWGAutodesk DWG TrueView免费查看；精修仍在 CAD 软件里
解压、截图/录屏做培训素材7-Zip；系统截图/录屏Win+Shift+S（截图与录屏都在这里）

③ 如何让 Cursor 帮你装（现场可照念）

名词先弄懂（给非程序员）
winget＝Windows 自带的「用一句话装软件」工具（有点像应用商店的命令版）。不会用没关系——更稳妥的是让 AI 给你官网下载链接，你双击安装包、一路「下一步」。
验证＝确认「真的装好了」。在 Cursor 打开终端（菜单 终端 → 新建终端，或 Ctrl+J），分别粘贴下面命令回车：
  • WPS/Office：能打开 Excel / 表格就算好
  • Python：python --version → 出现 Python 3.x… 即成功
  • Git：git --version → 出现 git version 2.x… 即成功（第 07 章推 GitHub 前必查）
若提示「不是内部或外部命令」→ 还没装好，或安装时没勾选「添加到 PATH」；装完后建议关掉再开 Cursor 再测。
⚠️ 装软件 = 高风险操作
必须每条命令你看过再执行；公司电脑遵守 IT 规定。Agent 不会、也不该静默装系统软件。
  1. Ask：「我要做箱单 + 偶尔 OCR + 批量改文件，还要推 GitHub。Windows 上建议装什么？请用大白话列出清单和用途；优先给官网安装方式，winget 命令写可选。」
  2. Agent：「按清单帮我装。先把完整步骤/命令给我看，我确认一步你再做一步。我不太会终端，步骤请写到小白能照做。」
  3. 验证：Office/WPS → 能打开表格；Python → python --version；Git → git --version。看到版本号 = 成功。

记一句：缺什么工具 → 先 Ask 清单 → 再确认后安装 → 验证（能打开或看到版本号）→ 才派活。

补充知识 · IDE（不单开一章）

IDE 里的 Agent 面板：模式已经和 Window 对齐

打开 IDE 后，输入框旁的模式菜单同样是：Agent · Plan · Debug · Multitask · Ask（Agent 旁常见 Ctrl+I）。选模式的规则两边一样，不必当成两套产品学。

日常派活用 Window 仍够用。再切 IDE，主要是这些场景：

  • 自己改几个字 / 用 Tab 补全、选中后 Ctrl+K 内联编辑
  • 要并排盯很多文件、用 VS Code 扩展、源代码管理面板

怎么切到 IDE（主路径）：

  • 快捷键 Ctrl+Shift+N
  • 或点窗口右上角常见的 IDE 按钮（带右斜向上箭头 ↗）

回到 Agents Window：再用一次同类入口 / 命令里的 Open Agents Window（以你界面实际按钮为准）。

快捷键别混：在 IDE 编辑区且已选中文字 时，Ctrl+K 才是内联编辑；在 Agents Window 里同一个键往往是搜历史对话。

🎤 讲解要点
主线演示全程留在 Window。 工具链要亲手装一条、验证一条才记得住。切 IDE：Ctrl+Shift+N 或右上角 IDE↗。肌肉记忆：派活在 Window，精修才回 IDE。
02 · 核心 · Agents Window

怎么跟 AI 打交道：先选模式，再下命令 Talking to the AI in Agents Window

场地 · Agents Window
这一章在 Agents Window 演示；IDE 侧栏是同一套模式菜单。逻辑两层：① 先决定"让它到什么程度"（模式）→ ② 再描述任务、审核结果。Tab / Ctrl+K 见第 01 章补充。

模式 = 让 AI 走多远

输入框旁下拉（Window / IDE 一致），常见顺序：Agent → Plan → Debug → Multitask → Ask。

模式会不会动文件什么时候用（业务话）心智比喻
Agent（常用默认）会，直接改（改完你审核）改周报、改箱单、批量处理——日常派活直接派他去干活
Plan先出方案，你确认后才动步骤多、怕改错、要先对齐口径先给你一份施工图
Debug会（为查清原因可能改/加检查）数字对不上、位号被误改、反复修不好——先查原因再动手带着证据找问题
Multitask会（多路并行）可拆开的大活（进阶，本场不深练）几个助手同时干
Ask不会，只回答问清楚、学项目、弄懂它为什么这么改问同事，不让他动手

主线练好 Ask / Plan / Agent；碰到「怎么查错了」再用 Debug。Multitask 知道有即可。

✅ 口诀
不确定 → Ask；大事 → Plan；小事 → Agent；对不上/查不清 → Debug。 面板点选，或 Shift+Tab 循环切。

在 Window 里完整走一遍 Agent

最常用：描述目标 → 它读文件并直接改好 → 你在「改动的文件」里点开核对。注意：现版 Agents Window 常常不会先弹出「接受 / 拒绝」让你点一下才写入——很多时候改完就已经进文件了，所以更要养成核对习惯。

⚠️ 新人第一原则
Agent 会动真文件。改完立刻点开看：绿/红对照懂不懂？不对就 Ctrl+Z 或让它改回去；看不懂先切 Ask 问「你为什么这么改」。你永远有最终决定权。
🎤 讲解要点
现场让同事：Ask → Plan → Agent 做小改动，并强调现网真相——别等「Accept」按钮，改完就要自己点开文件看。不对就撤销/重说。Tab/Ctrl+K 见第 01 章，今天主线不练。
03 · 核心

怎么让 AI 更准：喂对上下文、说清需求 Make it accurate: context & clear prompts

场地 · Agents Window
AI 不准，90% 是因为没给对信息或需求太模糊。这一章三招：@ 引用、选中文字送进对话、把需求说清楚。

第一招：@ 引用，手动指定"看哪里"

在对话框输入 @，弹出列表，点选即可——相当于用手指出「看这个」。给不给 @，结果差很多：

@ 什么例子作用 / 会得到什么
@文件@周报.md让它重点看这个文件，回答/修改都基于它（最常用）
@文件夹@助手生成文件/限定在某个目录里找、改，不乱翻别处
@Web@Web 2026 最新报关要求若列表里有：联网搜资料；没有就用浏览器查完再把要点贴进对话
拖入图片 / PDF截图、扫描件、说明书 PDF照着图做、从扫描件抽文字要点（复杂扫描可配合 OCR 工具）
小提示
不确定文件名时：先 Ask「这个文件夹里跟周报相关的文件有哪些？」再对点名的文件打 @。也可以从资源管理器把文件拖进对话框，效果类似 @。
用 Agent 改完后：点开被改的文件核对一眼（现版常直接写入，见第 02 章）。

第二招：选中一段话 → Add to Chat / Side Chat

在 Agents Window 打开的文件或预览里，用鼠标选中一段文字，上方会出现工具条（不用先复制）：

按钮快捷键做什么
Add to ChatCtrl+L把这段送进当前主对话，接着问或改（最常用）
Add to Side ChatCtrl+Shift+S送进侧边另一条对话；主线任务不换话题，适合另开一小问
和 @ 怎么配合
@文件 = 指出「看哪个文件」；选中送对话 = 指出「就看/就改这一小段」。比整段复制粘贴更干净，也比只 @ 整个文件更精确。
例：选中「以公司规定为准。」→ Add to Chat → 再打「改成更短的一句，语气正式」。

第三招：把需求说清楚（同样的活，说法不同结果天差地别）

✅ 好需求公式
做什么 + 在哪做 + 什么要求（约束）。
❌ "帮我优化一下"
✅ "把 @周报.md 的销售段整理成 5 条要点，每条 ≤20 字，保留数字，用中文"
✅ 箱单类："把 @Packing List….xlsx 的 /X 定成 /105，不要改位号，并写变更记录"
现场可练一句
打开真实项目文件 → 选中一段 → Add to Chat，问「用三句话概括」。再试一次 Add to Side Chat 另问一句。也可配合 @某文件，再切 Agent 做一处小改动并核对。
🎤 讲解要点
现场对比：先故意打一句模糊的看它反问，再补 @ / 选中段落 / 约束看它一次做对。记住："它不是不聪明，是你没告诉它去哪看、要什么、什么不能碰。" 对话开太久会变笨 → 换任务就新开（详见第 06 章）。
04 · 提效

Canvas：把数据/内容变成能交互的看板 Canvas: turn content into a live, iterable artifact

场地 · Agents Window
Canvas 是「边聊边生成、能实时预览、还能反复迭代」的画布。下面演示会走完三版：v1 柱状图初版 → v2 加环比列 → v3 更新 7 月数据，请盯着图表怎么变。

怎么用到 Canvas？
在 Agents Window 用大白话说即可，例如：「用这份销售数据做个可交互看板」。Agent 会生成 Canvas；之后继续说「加环比」「更新 7 月」就能迭代。不必先背菜单名。
演示里你会看到什么
4 张 KPI、带坐标轴的柱状图、可增列的明细表、区域横向条——对应真实「销售周报看板」场景，不是一张空壳图。
和普通聊天的差别
聊天给你一段文字；Canvas 给你一个能预览、能一句话继续改的成品（加列、加月份、换口径），改到满意为止。部署成手机可打开的网页——后文再专讲。
🎤 讲解要点
播完演示后，指着三处变化讲：① 绿色环比列、② 第四根柱、③ KPI 数字。强调「迭代」——第一版永远不完美，价值在于大白话连续改。本课件网页也是同类产物。
05 · 重点 · 落地

Skills & Rules：把公司的重复工作"固化"下来 Skills & Rules: lock in your repeatable workflows

场地 · Agents Window
对公司价值最大的一章。每月都要做、步骤固定、又容易出错的活——就是 Skill 的对象。主线：CMEC 箱单三件套。成果文件都可点开。

先分清：Rules 和 Skills 有什么不同

Rules（家规）Skills（专项流程）
是什么项目/团队的长期规矩某类任务的标准作业流程 SOP
什么时候生效每次对话自动生效需要时被触发（说到相关关键词就用）
放哪项目根目录的 AGENTS.md（或 .cursor/rules/）项目里 .cursor/skills/名字/SKILL.md；也可放在个人 Skills（全项目可用）
典型内容"始终中文回复""不许乱动没点名的文件""命名规范""箱单三件套怎么做、硬约束、禁止事项、检查清单"
一句话怎么说话、什么不能碰某件事怎么一步步做对

不会写文件也没关系：口述流程 → 让 Agent「整理成 Skill 草稿」→ 你核对硬约束和禁止项 → 再保存。跑完同样要点开产物核对。

Rules 演示：加不加"家规"的差别

主线案例：CMEC 箱单三件套 Skill

背景（这活为什么烦）：每批货要同时做三张表——Packing List（汇总箱单）、Detailed（明细）、Shipping Marks（唛头）。规则很死：

  • 三张表的箱号必须逐字一一对应（唛头 Packages No. = 箱单 BOX No.）；
  • 箱号格式 前缀-序号/总件数，定稿前总件数写 /X，定稿时统一改成真实总数；
  • 改 /X→/N 时绝不能误伤位号（如 PPP-PCS-MAR-104 里的 104 不是件数！）；
  • 每次改表必须写变更记录。

人工做：慢、枯燥、一不留神就把位号当件数改了，三表还容易对不上。

# 每次改表必写 变更记录.md
  • 提炼流程：把这件事「怎么做对 + 有哪些坑」口述给 Agent，让它先整理成草稿。
  • 存成 Skill：保存为 SKILL.md；开头用一两句话写清「什么时候该用这个流程」（对应文件里的 description）。
  • 补硬约束和禁止项：把「绝不能做的事」写进去（防错关键，如「不要改位号」）。
  • 用一次、修一次：说相关关键词触发跑一遍，哪里不对就补进 Skill，并点开产物核对。
    • ✅ 为什么这对公司值钱
    Skill 把"老师傅脑子里的经验"变成可复用、可传承、不走样的文件。新人一句话就能跑出老师傅级别的结果，还不会犯那几个致命错误。一次编写，整个团队反复受益。
    🎤 讲解要点
    这里一定用你们自己真实的重复活当例子（箱单、报价单、周报模板、命名规范都行）。先演示"随口让它改 → 出错"，再演示"有 Skill → 一句话做对 + 自动写变更记录"。同事看到自己天天头疼的活被一句话搞定，才会真正想学。
    06 · 把关

    安全与把关：AI 会犯错，你得会兜底 Safety: review, rollback, privacy

    AI 很强但不是永远对。用得放心的关键是三件事：改完点开核对、随时能回退、知道数据去哪了。

    Review：改完点开核对

    回退：改坏了不怕（课上以这两条为准）

    Ctrl+Z / 让它改回去

    刚改错可撤销；或说「把刚才改动撤回去」。现版未必有「先接受再写入」，撤销更常用。

    Git 版本（最稳）

    重要工作先提交一次（第 07 章），随时回到任意历史版本——培训现场也按这个练。

    上下文别开太久 + 隐私

    ⚠️ 对话太长会变"笨"
    一个对话聊太久、掺太多话题，AI 会抓不住重点。换任务就新开对话。
    要接着旧话题：优先在历史列表里打开那条旧对话继续聊；或把关键几段复制进新对话。
    需要把整段对话存成文件时：打开该对话后，点对话区右上角（靠近「IDE↗」一侧）的 ··· 菜单 → Export。注意：右侧「改动的文件」栏里没有 Export；必须点对话面板自己的 ···。
    🔒 隐私怎么关数据共享（现版界面）
    打开 Cursor Settings → General，滚到最底部 Privacy。
    现版常见显示是 「Data Sharing Enabled」（数据共享已开），右边有 Configure——点它，在选项里改成不共享 / Privacy（名称以你下拉菜单为准）。
    不要找名叫「Privacy Mode」的独立开关——很多版本已经改成上面这种「状态 + Configure」。
    网页备用：cursor.com/dashboard → Settings。
    无论哪种状态：密码、密钥、未公开客户数据都不要贴进对话。团队版可能被管理员锁定。
    🚫 什么时候别让 Agent 自己来
    删文件/删库、改权限、生产环境配置、你完全看不懂的大改动——先 Ask 问清楚，或找同事确认；已改错就立刻撤销，别放任不管。
    🎤 讲解要点
    三条安全带：① 改完点开核对 ② 能回退（Ctrl+Z / 让它改回 / Git）③ 隐私：General 底部 Privacy → Configure（你截图里若是 Data Sharing Enabled，就点这里改）。Export 只在对话右上角 ··· 里。一句话："AI 负责快，你负责对。"
    07 · 协作

    配合 GitHub：备份到云端 GitHub · publish once, then Commit + Push

    GitHub = 云端备份文件夹（个人使用免费）。本场只练通一条线：有 Git → 第一次发布 → 以后改完：先 Commit，再 Push。官网 github.com。

    路线图：①确认 Git → ②打开源代码管理 → ③第一次发布 → ④日常用 Commit / Push → ⑤可选 Pages。

    ① 确认本机装了 Git

    终端输入 git --version，看到 git version 2.x… 即可。没有就先装 Git for Windows（第 01 章），装完重启 Cursor。

    面板写「没有 Git 存储库」= 这个文件夹还没被 Git 管住，不等于没装软件。

    ② 打开「源代码管理」（建议在 IDE）

    Agents Window 先 Ctrl+Shift+N 或右上角 IDE↗，再任选一种打开方式：

    • Ctrl+Shift+G
    • 左侧活动栏「分支 / 源代码管理」图标
    • 菜单 查看 → 源代码管理

    ③ 第一次发布（只做一次）

    看面板上出现哪一种，二选一即可：

    你看到的怎么做
    两个蓝按钮：初始化仓库 / 发布到 GitHub直接点 发布到 GitHub（会顺带初始化；一般不必先点「初始化」）
    已有改动列表 / 提交框，顶部有 Publish Branch 或「发布分支」点 Publish Branch → 选 GitHub → 填仓库名
  • 确认打开的是整个项目文件夹。
  • 按上表点发布；若弹出登录窗口，用浏览器里已登录的 GitHub 账号完成授权即可。
  • 选仓库名、Public（公开）或 Private（私有）→ 确认发布。
  • 浏览器打开 github.com，确认文件已出现。
    • 发布成功后，「发布到 GitHub」会消失
    这是正常现象：第一次已经挂好远程仓库了。以后不要再找发布按钮；有改动时用下面的 Commit 和 Push。

    ④ 以后日常：Commit 和 Push（两个按钮）

    先记住：没改文件时，上面往往是空的
    只有改了文件并保存后，源代码管理里才会出现「更改」列表（列出改了哪个文件）。没改动时，不要干等 Commit 面板——那是正常的。
    保存文件（Ctrl+S）只是写进当前文件夹；Commit 才是在项目里的 .git 记一笔本地版本；Push 才上传到 GitHub。

    界面上是两个分开的按钮，不是写死「Commit → Push」一条。常见顺序：有更改 → 先 Commit → 再 Push。

  • 改文件并保存 → 左侧出现「更改」和文件名（这时才有东西可提交）。
  • 点 Commit：写一句说明（中文即可；Cursor 也常会自动生成）→ 提交到本地 .git。
  • 点 Push（或同步）：把刚提交的内容上传到 GitHub。Push 一般不用再写说明。
    • 你看到的是什么
    上面的「更改」+ 文件名有未提交的改动时才出现；列出本次改了哪些文件
    Commit把当前改动存成一次本地版本（说明可中文）
    Push / 同步把已 Commit 的内容上传到 GitHub
    Agent Review / Find Issues可选：让 AI 检查改动；跟备份无关，不点也能 Push
    再往下那一串圆点历史记录（以前的 Commit），不是待办。最上=现在；下面=更早。有云图标≈已在 GitHub

    词义：仓库=云端项目文件夹；Public / Private=公开 / 私有（公司材料用 Private）。

    ⚠️ Push 失败？先查网络
    GitHub 在国外，国内有时连不上（超时、重置）。可先重试；仍不行用公司允许的稳定网络或 VPN 再推。本地 Commit 已成功的话，改动还在，网络好了再 Push 即可。

    ⑤（可选）用 Pages 挂成网页链接

    网页文件名尽量用英文（如 cursor-course.html）。中文名在手机里点链接常失败，只能复制粘贴。

  • HTML 已经 Push 上去。
  • 仓库 Settings → Pages → Source 选 Deploy from a branch → Branch 选 main、文件夹 /（root）→ Save。
  • 发链接时必须带上后面的文件名，例如 https://用户名.github.io/仓库名/cursor-course.html。只发到 …/仓库名/ 没有首页文件时会 404。

    • 练习清单

    • ✓git --version 有版本号
    • ✓会打开源代码管理（Ctrl+Shift+G）
    • ✓第一次发布成功，网页能看到文件
    • ✓知道：只有改了文件，「更改」列表才会出现
    • ✓再改一点：先 Commit，再 Push
    • ✓（可选）Pages 出一个链接
    🎤 讲解要点
    只抓一条线：version → 第一次发布 → 网页看见文件 → 有更改才 Commit，再 Push。没改文件时提交区可能是空的；底下圆点是历史。分支、PR 本场不展开。

    09 · 拓展

    拓展：主线之外，后续会深入挖的专题 Explore · deepen topics after the core track

    主线（00–08）先把人带会上手；本区是持续更新的蓄水池——Cloud、No Repo、MCP、以及界面上还没用过的能力，不是一笔带过，而是后面要逐个研究清楚、做成可演示内容再补进来。课件会少大翻主线，多在这里加厚。

    怎么往这里加内容（维护约定）

    • 看官方 Changelog 和 文档，结合自己业务场景选题。

    和主线的关系
    主线（Ask → Plan → Agent → 核对 → Skill → GitHub）保持稳定、少大翻；拓展区按专题加深，一项项做实，不要求第一次培训讲完。
